# 04 · 编码规范

> 目的：模块化、可维护，新增模块互不污染。后端 Go / 前端 React+TS。

## 后端分层（Go）

```
backend/
├── main.go                 # 只做：开库 → 建表 → 装配路由 → 启动（无业务代码）
└── internal/
    └── <模块>/             # 一个业务域一个包，如 trade
        ├── model.go        # 数据结构 + json 标签（无逻辑）
        ├── store.go        # 数据库访问（建表/增删改查/聚合），不碰 HTTP
        └── handler.go      # HTTP 绑定 + 参数校验 + 响应，不碰 SQL
```

### 新增模块步骤

1. 建 `internal/<模块>/`，复制 model / store / handler 三件套。
2. `main.go`：`store := x.NewStore(db)` → `store.Migrate()` → `x.NewHandler(store).Register(r)`。
3. 路由统一挂 `/api/<模块>` 前缀。

### 规则

- 导出标识符用英文，注释用中文。
- 错误向上返回，由 handler 统一转成 `{"error": "..."}` + 对应状态码。
- JSON 字段小驼峰，与前端 TS 类型一一对应。

## 前端（React + TS）

- 类型放 `src/types.ts`；接口调用放 `src/api.ts`；页面按模块拆组件。
- 函数式组件 + hooks。
